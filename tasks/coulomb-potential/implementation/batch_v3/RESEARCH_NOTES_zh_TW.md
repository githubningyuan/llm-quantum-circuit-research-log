## B. 建議的研究策略／待驗證假說

1. **將 MAP-Elites 的局部分支進步視為搜尋進展，但需驗證保留且設定最低改善幅度**。v3 可選 `--max-no-progress N --min-parent-improvement-pct 1.0`；經 v6.2 獨立複驗，並於既有資料庫重載後仍存在的子代，比父代至少低 1%，即可重置停滯計數；刷新全域最佳也會重置。百分比 **1% 是控制成本的工程起點，不是論文規定或最佳統計閾值**。單純提交子代／不同 SHA／相同 T×Q，不算足夠進展。
2. **研究記憶**：上次成功、失敗架構與解釋可能提高每美元產出，但尚未 A/B 驗證。v3 **只記錄資訊供人稽核，不把本文塞進 OpenCode Session**；真正注入短期記憶會改變既有提示詞與成本，須另開受控實驗及安全驗收。
3. **低／高推理強度比較**：目前保留原實測 `low`；應先比較既有 session 的首次編輯、首次有效評估時間、子代分布、模型 tokens 與美元花費。`high` 只應在隔離、有限預算下 A/B 測試，不能直接替換驗證中的流程。
4. **Subagent**：可作為日後「唯讀研究顧問」實驗，不應現在放開主 Agent 的權限、讓子代理修改候選或操作評估器。是否有幫助，需量化改善／token 與成本。
5. **父代抽樣／探索多樣性**：靜態 `random_seed=42` 每輪重建物件可能影響隨機起點；尚無充分實驗證明選父代重複，因此**不得擅自改種子**。保留所有父代 SHA 與 T×Q，以精確 SHA 比對確認是否使用前一輪子代。
6. **成本量測**：VM 待機費與 DeepSeek API 費需分開記錄。先前約 US$1.86 API／US$43.48 GCP 是舊時點快照，**非此刻總成本**；也沒有可驗證的作者原始總花費可直接比較。
7. **限制範圍**：只重現 Coulomb；不擴到其他 7 個任務，不改 OpenEvolve 特徵設定、不改 `quantum_evaluate`、不變更 OpenCode 安全權限、不移動工作區保護電路。

## C. v3 究竟吸收了什麼？

- **已變更外層決策**：可選的「連續 N 輪沒有全域改善，**也沒有已保留子代相對父代 ≥ X% 改善**」停止規則。保留原 `--max-no-best` 可相容舊批次，但不建議用來判定 MAP-Elites 停滯。
- **已變更留存證據**：每輪記錄父代 SHA、子代 SHA、保留到 DB 的子代、父代改善率、跨輪父代是否是上一輪的真子代；唯讀報表可推算 v2 歷史分支。
- **沒有改變**：DeepSeek Prompt、歷史記憶注入、Subagent、推理強度、父代取樣、原始工具與權限、量子評估器、工作區最佳電路。
- **未完成的研究**：上次 593,553 分支的**真正 SHA** 需要從 GCP `batch.json` 列出的子代確認。若想在下一輪強制從它開始、比較 high/low 或加入研究記憶，必須另行做受控實驗，不能宣稱已實作。

## D. 與使用者原始目標對齊

評估核心是：經原始評估器獨立驗證的 Coulomb T×Q 改善幅度、真實 API+VM 美元成本，以及可公開重現的完整工作流程。工作自動化／監控是手段，不能替代物理電路的成果。
